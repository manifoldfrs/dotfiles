# MCP Configurations

Model Context Protocol (MCP) server configurations shared across coding-agent harnesses.

## Source of truth and sync

Pi's [`stow/pi/.pi/agent/mcp.json`](../stow/pi/.pi/agent/mcp.json) is the canonical definition for the six shared MCP servers.
Edit shared servers there, then sync the other harnesses:

- **Codex and OpenCode:** run `./scripts/harness_sync.sh` to regenerate their server blocks from Pi's config (`scripts/validate-dotfiles.sh` fails if they drift).
- **Claude Code:** run `./mcp_setup.sh install-claude` to import Pi's servers into machine-local `~/.claude.json`.

| Harness | Config file | How it stays in sync |
| --- | --- | --- |
| **Pi** (source) | `~/.pi/agent/mcp.json` → `stow/pi/.pi/agent/mcp.json` | Canonical tracked source |
| **Codex** | `~/.codex/config.toml` → `stow/codex/.codex/config.toml` (macOS only) | Generated by `./scripts/harness_sync.sh` while preserving `node_repl`, `computer-use`, the direct `xai-search` server, and per-tool approvals; Linux/`agentbox` keeps a machine-local `config.toml` |
| **OpenCode** | `~/.config/opencode/opencode.jsonc` → `stow/opencode/.config/opencode/opencode.jsonc` | Generated by `./scripts/harness_sync.sh` |
| **Claude Code** | `~/.claude.json` | Machine-local registrations imported by `./mcp_setup.sh install-claude` |

## Configured servers

The Exposure column below applies to Pi and Codex Code Mode; OpenCode sets `codemode: false` for Ref and Exa, and Claude Code's import strips `exposure`.

| Server | Purpose | Exposure | Auth / notes |
| --- | --- | --- | --- |
| **Ref** | Library and framework documentation search | Direct (and Code Mode) | `REF_API_KEY` |
| **Exa** | General web search and page fetching | Direct (and Code Mode) | `EXA_API_KEY` |
| **Jev** | Typed judgments from TypeSafe's Jev model | Code Mode | `TYPESAFE_API_KEY` |
| **Chrome DevTools** | Isolated browser inspection, console, network, screenshots | Code Mode | Isolated Chrome with usage statistics disabled; never attaches to your personal browser profile |
| **HEY** | Mail, calendars, todos, and contacts via `hey mcp` | Code Mode | Keychain credentials from `hey auth login`; read/write by default |
| **Superlogical** | Rex Beta docs, changelog, and community feedback | Code Mode | OAuth via `/mcp` after registering |
| **xai-search** (Codex) | Live X posts and web search | Direct (and Code Mode) | Grok Build sign-in or `XAI_API_KEY` |

To restrict HEY to read-only access, change its `args` to `["mcp", "--read-only"]` in `stow/pi/.pi/agent/mcp.json`, run `./scripts/harness_sync.sh` for macOS Codex and OpenCode, and re-import Claude Code after running `claude mcp remove --scope user hey`.
If HEY is registered in a Linux/`agentbox` machine-local `~/.codex/config.toml`, also set `args = ["mcp", "--read-only"]` in its `[mcp_servers.hey]` block.
Run `/reload` in Pi and restart every affected Codex, OpenCode, or Claude Code session before relying on read-only access.

## API keys

Export API keys from machine-local `~/.config/bash/local.bash` (never tracked):

```bash
export REF_API_KEY="..."
export EXA_API_KEY="..."
export TYPESAFE_API_KEY="..."
```

Leave `${ENV_VAR}` placeholders, `env_http_headers`, and `env_vars` references unchanged in tracked files.
Never embed API keys in URLs or literal `env` tables in tracked configs.

## Per-harness setup

### Pi

Pi is Stow-managed by the default dotfiles profile:

```bash
cd ~/code/personal/dotfiles
./scripts/stow.sh apply
pi list
pi mcp list
```

`stow/pi/.pi/agent/settings.json` enables Pi's built-in MCP support and Codemode alongside the normal coding tools.
Run `/reload` or restart Pi after changing `~/.pi/agent/mcp.json`, and run `/mcp` inside Pi to complete OAuth for Superlogical.
Adding entries to `mcp.json` does not install their underlying packages or configure the browser bridge.

### Codex

On macOS, Codex's `config.toml` is Stow-managed by the default dotfiles profile (on Linux/`agentbox`, `scripts/stow.sh` skips `.codex/config.toml` so the host keeps a machine-local Codex config):

```bash
cd ~/code/personal/dotfiles
./scripts/stow.sh apply
codex mcp list
```

Restart Codex to pick up server changes.

- **Code Mode:** Codex enables native Code Mode (`features.code_mode`).
  Ref and Exa are exposed both directly and in Code Mode; Jev, Chrome DevTools, HEY, and Superlogical are exposed only in Code Mode (matching Pi).
  Do not disable Codex Code Mode and expect Code-Mode-only MCP tools to remain callable.
- **Pi-only APIs:** Codex uses its own JavaScript tool interface; shared MCP calls work there, but Pi's `models.classify` API and `jev_pipeline` extension tool do not carry over.
  Use Jev's MCP classifier tools in Codex and run Pi-native workflows in Pi.
- **`xai-search`:** Install [Grok Build](https://x.ai/build) and run `grok login` to use the signed-in CLI from Codex.
  The Grok Build route requires a completed search event for every requested source.
  For exact date, handle, media, or domain filters and output-token caps, set `XAI_API_KEY` in Codex's launch environment to select the direct [xAI Responses API](https://docs.x.ai/developers/tools/x-search) route.
  The API route defaults to `grok-4.7` and uses API billing.
- **ChatGPT app servers:** sync keeps the `node_repl` and `computer-use` entries installed by the ChatGPT app.

### OpenCode

OpenCode is Stow-managed by the default dotfiles profile and receives its server block from `./scripts/harness_sync.sh`.
Apply Stow and restart OpenCode after running the sync script.

### Claude Code

After approving a live configuration change, import the six shared servers from Pi's tracked config:

```bash
./mcp_setup.sh install-claude
claude mcp list
```

The import strips Pi-only `exposure` and `timeout` fields, sets `type: "stdio"` for command servers, and preserves `${ENV_VAR}` placeholders.
Registrations are user-scoped and leave unrelated Claude account connectors untouched.
Re-running skips identical registrations; if an existing registration differs, the import stops without overwriting it.
Review any conflicting server before removing it with `claude mcp remove --scope user <name>` and re-running the import.
Restart Claude Code after registering servers.

## Backup

To capture your current machine-local Codex config (including any literal API keys) into gitignored `mcp/codex_config.toml`:

```bash
./mcp_setup.sh backup
```

Stow-managed configs use environment interpolation and contain no secrets.
