# Open Pstack skills

This guide summarizes all 65 skills installed with Open Pstack 1.21.0 from their local `SKILL.md` definitions so you can pick the right Codex skill for a task.
Each definition lives at `~/.codex/plugins/cache/open-pstack/pstack/1.21.0/skills/<name>/SKILL.md`.
[Open Pstack upstream](https://github.com/ericlitman/open-pstack)

| Codex skill | What it does |
| --- | --- |
| `$pstack:architect` | Grounds a non-trivial design with `$pstack:how`, runs `$pstack:arena` to compare at least two distinct type and module sketches, and implements directly against the synthesized contract. Proceeds straight into coding unless you ask for a checkpoint, and restarts from scratch if repeated implementation friction exposes a broken shape. |
| `$pstack:arena` | Runs N parallel candidates against one shared prompt and a 3-6 point rubric in isolated worktrees or temp directories, scores them with an optional cross-provider judge, picks a base, and manually grafts strong ideas from losing candidates before verifying the result. Returns one merged artifact with a synthesis note recording grafts, rejections, and any runner dropouts. |
| `$pstack:automate-me` | Reads recent workspace transcripts in parallel slices, asks targeted preference questions, and drafts or updates a personal `<handle>-mode` skill cleaned with `$pstack:unslop`. Confirms whether to update an existing mode skill first, reviews and revises the draft with you before committing and opening a PR from a worktree, and relies on Claude Code default transcript paths and skill-authoring tools that need Codex adaptation. |
| `$pstack:babysit` | Runs the standalone workflow for one open PR via `gh` CLI by fixing merge conflicts and failing CI, applying clear review edits, triaging review-bot comments, and pacing re-checks through Codex tool rules. Stops after three failed fix-push-recheck rounds, pauses for design choices or shared-branch history rewrites, and lets Poteto Mode use its own babysit playbook during Poteto Mode runs. |
| `$pstack:benchmark-checklist` | Vets a performance measurement against seven runtime checks covering bottleneck profiling, production tuning, physical math limits, error counts and output validity, five or more alternating runs, end-to-end impact, and proof that work ran inside the timed region. Outputs a verdict of faster, slower, no measurable difference, or inconclusive when key evidence is missing. |
| `$pstack:blast-radius` | Investigates downstream breakage beyond a diff across library internals, lifecycle timing, schemas, wire formats, and feature flags, then isolates the key fact the change depends on for safety. Runs a real script or test against the actual code to prove that fact, lists confirmed risks alongside cleared checks, and marks any unverified safety claim unproven. |
| `$pstack:bro` | Rewrites the previous assistant message in shorter, plain language stripped of technical jargon. |
| `$pstack:correct` | Reviews commits, reverts, and review comments for repeated agent mistakes, then fixes top classes in priority order with architecture, types, lints naming the fix, behavior tests, or docs last. Proves each new check fails on a real past mistake, updates the enforced-rule table in agent instructions, reports each class with its evidence and chosen level, requires a reason, expiry date, and human approval for line-level exceptions, and runs only when explicitly invoked. |
| `$pstack:create-formal-verification-skill` | Picks a high-stakes concurrency, state-machine, or invariant target from the codebase, writes a project-local formal verification skill using a fitting tool such as TLA+ or a code-level verifier, and proves the skill catches a deliberate scratch break before handoff. Records covered files and a sync commit for later upkeep, reports any live property failure as a finding, and leaves product code untouched unless asked. |
| `$pstack:create-verification-skill` | Inspects the repo to generate a project-local `verify-<app>` skill and initial `features/` map with concrete launch, doctor, driving, evidence, and cleanup steps for your app's UI, CLI, or service. Proves the generated skill once end to end on one mapped feature, checks that proof artifacts survive teardown, and cleans up every process it started. |
| `$pstack:deslop` | Cleans the branch diff against `main` by trimming unnecessary comments, abnormal defensive checks or `try/catch` blocks, `any` type-bypass casts, and deep nesting fixable with early returns. Preserves existing behavior except for clear bugs and ends with a short summary. |
| `$pstack:figure-it-out` | Builds and runs a custom multi-phase playbook for large or unattended changes by defining a testable done condition, capturing a baseline check harness before editing, and running each small unit as a test-or-revert step. Presents the framing and tradeoffs before a long run, logs decisions with `$pstack:show-me-your-work`, and reports the playbook, rigor level, trail path, verified results, and open work. |
| `$pstack:fix-ci` | Inspects failing PR checks via `gh pr checks` and job logs or external check links, applies the smallest focused fix one failure at a time, pushes, and re-checks until CI turns green. |
| `$pstack:fix-merge-conflicts` | Detects and resolves git merge conflicts non-interactively with minimal edits, regenerates lockfiles through package manager tools, validates with build, lint, and tests, and stages the resolved files. Leaves git pushes and tags untouched. |
| `$pstack:get-pr-comments` | Fetches review and discussion comments from the current branch's active PR, groups them by severity and actionability, and returns a prioritized action list with open questions. |
| `$pstack:how` | Explores the codebase in read-only mode to explain how a module or subsystem works and where new code belongs, using one pass for narrow questions or 2-4 parallel explorers plus a synthesizer for cross-cutting systems. Outputs structured sections covering overview, key concepts, runtime flow, file locations, and gotchas. |
| `$pstack:in-your-own-words` | Restates the assistant's understanding of your goals and the problem you want to solve so you can catch misalignment early. Runs only when explicitly invoked. |
| `$pstack:interrogate` | Launches parallel adversarial reviewers in isolated git worktrees to break a diff, branch, or design, then reruns every reported command to keep only failures proven by real output against the restated intent. Reports verified findings and drops unrun claims and style nits, applying zero code fixes. |
| `$pstack:ketchup` | Summarizes what changed in the current chat since your last message in plain language and small visuals, then lists every pending decision or approval with options, recommendations, evidence, and risks so you can act from the reply alone. Runs only when explicitly invoked and stays strictly read-only. |
| `$pstack:ketchup-video` | Produces a `$pstack:ketchup` catch-up as a short silent subtitled slide video (up to 10 slides built from real screenshots, diffs, and data) with waiting decisions listed as text below it. Runs only when explicitly invoked and stays read-only inside the repo, writing rendered media outside the repository. |
| `$pstack:maintain-formal-verification-skill` | Audits project-local formal verification skills after code changes by diffing covered files since the sync commit, updating models or harnesses from current code, rerunning checks, and injecting a deliberate break to confirm passing checks still catch bugs. Runs only when explicitly invoked, classifies each failure as verification drift or a real code bug, and edits only verification artifacts unless asked to touch product code. |
| `$pstack:maintain-verification-skill` | Audits a project-local verification skill and feature map by launching parallel read-only source readers per feature file and then running a live pass that health-checks and exercises every mapped feature. Edits only the verification skill directory, reports real app regressions separately, and opens at most one PR of proven doc or harness fixes. |
| `$pstack:make-pr-easy-to-review` | Prepares a PR for faster review by improving its description, separating core and mechanical files, calling out risks, and optionally reorganizing noisy commits into dependency order. Proposes a plan for approval before rewriting history or force-pushing, verifies the resulting git tree matches the original, and recommends splitting PRs that are too large to tidy with notes. |
| `$pstack:no-comments` | Runs a comment-audit subagent (`comment-sicko` on Claude, mapped via Codex tool rules) on the target diff, reviews its deletions and flags, applies small in-scope root-cause fixes for accepted findings, and offers to replace constraint comments with types, runtime checks, tests, or lints. Needs approval before encoding constraint checks, stops and fails if a second subagent pass is rejected, and reports deletions, restores, fixes, encodings, and open work. |
| `$pstack:poteto-help` | Answers questions about Open Pstack setup, model configuration, playbooks, principles, and choosing the right skill, returning an example prompt and upstream links based on your local config state. Runs only when explicitly invoked and returns a prompt for help questions so you decide when to start a token-heavy run. |
| `$pstack:poteto-mode` | Activates Open Pstack's full workflow mode, matching your task to a bundled playbook, tracking its steps, routing subagents by configured model roles, and pulling in specialized skills and engineering principles as needed. Proceeds autonomously on reversible work and pauses before irreversible actions like shared-branch force-pushes, deploys, data deletion, or customer messages. |
| `$pstack:principle-attack-the-premise` | Stops repeated patching when debugging stalled loops after two or more fixes sharing one assumption fail the same gate, requiring you to write down and directly test that assumption before trying another fix. |
| `$pstack:principle-boundary-discipline` | Keeps input validation, parsing, and error handling at system edges like CLIs, configs, adapters, and external APIs so core logic stays in pure, framework-free functions that trust internal types. |
| `$pstack:principle-build-the-lever` | Turns non-trivial edits, migrations, analyses, or checks into a small rerunnable script, codemod, generator, or delegate skill after prototyping one unit by hand so reviewers get a deterministic artifact to rerun. |
| `$pstack:principle-encode-lessons-in-structure` | Turns recurring corrections or repeated instructions into lint rules, metadata flags, runtime checks, or scripts, falling back to clear written examples only for pure judgment calls. |
| `$pstack:principle-exhaust-the-design-space` | Starts novel UI, product-feel, or architecture decisions that have no local precedent with 2-3 competing prototypes compared side by side before picking one implementation. |
| `$pstack:principle-experience-first` | Steers product, UX, API, and scope tradeoffs toward fewer polished features for end users, callers, and future maintainers, testing ideas with cheap throwaway prototypes first. |
| `$pstack:principle-explain-the-number` | Requires stating a decision threshold, profiling the real bottleneck, ruling out confounders like errors or untuned defaults, and attaching run counts and spread before trusting any perf or eval number, pairing with `$pstack:benchmark-checklist` for full performance vetting. |
| `$pstack:principle-fix-root-causes` | Guides debugging to reproduce the bug first, trace symptoms back to the earliest invalid decision or saved state, fix every matching fault site, and add guards only for valid states. |
| `$pstack:principle-foundational-thinking` | Orders design work by defining core data structures first, isolating concurrent state, and landing shared scaffolding like types, CI, and test harnesses before feature logic. |
| `$pstack:principle-guard-the-context-window` | Protects reasoning quality as context fills up by sending bulky reads, logs, and fan-out work to subagents, keeping short summaries in the main thread, and capping phase file and turn budgets. |
| `$pstack:principle-laziness-protocol` | Favors deletion, single-source-of-truth flags, and the smallest diff that solves the problem cleanly during edits and refactors. |
| `$pstack:principle-make-operations-idempotent` | Builds commands, lifecycle hooks, and loops from current observed state with atomic or content-checkable markers so retries and partial crashes reach the same end state. |
| `$pstack:principle-migrate-callers-then-delete-legacy-apis` | Guides internal API refactors with no external compatibility commitments to move all callers, update contract tests, and delete the old API in one coordinated wave. |
| `$pstack:principle-minimize-reader-load` | Cuts reading effort by removing single-caller wrappers and pass-through layers, narrowing broad interfaces, and shrinking mutable state toward pure functions and local variables. |
| `$pstack:principle-model-the-domain` | Replaces scattered conditionals, parallel booleans, and repeated shape checks with explicit structures like state machines, lookup tables, discriminated unions, or domain modules when complexity calls for them. |
| `$pstack:principle-never-block-on-the-human` | Keeps async work moving by making reasonable reversible decisions and reporting the result, pausing for confirmation only on irreversible actions like force-pushes, production data deletion, or external messages. |
| `$pstack:principle-outcome-oriented-execution` | For planned rewrites and migrations with explicit phase boundaries, converge on the target architecture without throwaway compatibility code: allow declared, scoped, reversible breakage with high-signal checks on actively touched areas at each phase gate, and require full static and runtime verification at plan completion. |
| `$pstack:principle-prove-it-works` | Requires checking the real running artifact, live state, or diff before calling work done, favoring rerunnable check scripts over proxies or compile-only checks. |
| `$pstack:principle-redesign-from-first-principles` | Fits a new requirement by rethinking the affected design as if it were built in from day one, rolling updates through types, docs, and examples in small steps. |
| `$pstack:principle-separate-before-serializing-shared-state` | Avoids concurrent write races by giving each actor its own file, branch, key, or state directory and merging at read time, using locks or single-writer phases only when one shared writer is required. |
| `$pstack:principle-sequence-verifiable-units` | Breaks sweeps, migrations, and stacked PRs into small units checked one by one on a clean base, ordering commits so each step proves the next like a failing test before its fix. |
| `$pstack:principle-subtract-before-you-add` | Starts additions, refactors, and rewrites by deleting dead code, redundant validators, speculative guards, and empty stubs first so new work lands on a simpler base. |
| `$pstack:principle-test-behavior-not-implementation` | Focuses unit and integration tests on observable outcomes like return values, error types, stored state, and external effects so tests catch behavior regressions and survive internal refactoring. |
| `$pstack:principle-type-system-discipline` | Uses static types to make invalid states unrepresentable by branding primitive types, parsing external data at boundaries, checking all variants exhaustively, and deriving types from authoritative schemas. |
| `$pstack:recall` | Reconstructs recent working context across workspace chat transcripts, shared records via `$pstack:why` investigators, and live `git` and `gh` state to return a brief with a capsule, status-tagged threads, recurring problems, and a next move. Defaults to a 7-day window in the active workspace, and its transcript path targets Claude Code's project log directory. |
| `$pstack:reflect` | Runs three parallel read-only reviewers (Judgment, Tooling, and Divergent) plus a citation-checking synthesizer over the active transcript or digest to turn session learnings into concrete edits on existing skills. Moves structurally enforceable rules to a backlog, skips trivial sessions, and applies only edits you approve. |
| `$pstack:setup-pstack` | Maps provider-qualified models and per-family effort levels to Open Pstack roles, probes each native and external lane before writing the override sheet for new sessions, and offers to set up project verification skills if missing. Reruns against an unchanged valid sheet skip setup prompts and rewrite the sheet once all probes pass. |
| `$pstack:sharpen` | Rewrites your draft prompt for greater depth by adding expert methods, raw material needs, and an outside check, then returns the revised prompt so you can send it when ready. Leaves the task itself unexecuted. |
| `$pstack:show-me-your-work` | Records an auditable TSV decision log for long-running, multi-phase, or unattended runs with one row per decision covering what changed, why, supporting evidence, and outcome. Keeps the log local by default and commits it when reviewers need the trail in a PR. |
| `$pstack:statechart` | Checks a TLA+ model of a stateful flow, protocol, or service, draws a Mermaid statechart showing normal transitions, failing paths, and states reached after a bug, and reports the shortest plain-language path to each broken rule. Above 500 states it draws only failing paths or writes no chart when every rule holds, stops follow-up checks at 100,000 states after the first break, and runs only when explicitly invoked. |
| `$pstack:swarm` | Fans out N parallel background workers across independent slices, coverage matrices, races, gauntlets, or exploration partitions, drains all lanes, and combines their findings into one report. Fits split workloads and parallel checks where each lane investigates a separate slice or races to a result. |
| `$pstack:tdd` | Drives test-first development by writing a failing or regression test before the fix when you explicitly ask for TDD or when an obvious cheap local test target exists. Skips test-first execution when test paths are unclear, slow, integration-heavy, or unrequested. |
| `$pstack:teach` | Runs `$pstack:how` and `$pstack:why` on a subsystem or change and weaves runtime architecture and historical rationale into one plain-language explanation. |
| `$pstack:technical-writing` | Applies a layered standard combining Diátaxis structure, Google developer style, STE instruction rules, and Global English syntax to draft or review docs, RFCs, READMEs, PR descriptions, and commit messages. |
| `$pstack:thermo-nuclear-code-quality-review` | Runs a strict maintainability audit that targets weak abstractions, oversized files, and tangled conditional logic. |
| `$pstack:typescript-best-practices` | Applies TypeScript coding and type-syntax conventions when reading or editing `.ts` and `.tsx` files. |
| `$pstack:unslop` | Strips AI-generated writing tells and boilerplate phrasing from any prose, including replies, docs, PR comments, commit messages, and skills. |
| `$pstack:what-did-i-get-done` | Summarizes git commits you authored during a specified time window into a concise status update. |
| `$pstack:why` | Discovers available MCPs and runs parallel investigators across source control, issues, docs, chat, observability, error tracking, and analytics to return a cited explanation of design rationale, tradeoffs, regressions, or thresholds. Reports empty searches as findings and flags any unavailable MCP it skipped. |
