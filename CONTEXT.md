# Dotfiles Context

This glossary defines the repository's language for moving configuration between version control, a live machine, and multiple coding-agent harnesses.

## Configuration lifecycle

**Tracked source**:
The version-controlled representation of configuration that this repository owns and can reproduce.
_Avoid_: Backup, live config

**Live configuration**:
The configuration a tool reads from the user's home directory on the current machine.
_Avoid_: Tracked source

**Stow package**:
A named collection of tracked sources that maps onto the same relative locations under the user's home directory.
_Avoid_: App, module

**Apply**:
Reconcile selected Stow packages into the live configuration, normally by creating or refreshing managed links.
_Avoid_: Install, deploy

**Capture**:
Copy current live configuration into tracked sources for review and possible commit.
_Avoid_: Backup

**Safety backup**:
A timestamped copy of conflicting live configuration preserved before this repository replaces or links that location.
_Avoid_: Capture, tracked source

**Machine-local state**:
Configuration, credentials, caches, sessions, or logs that belong to one machine and remain outside version control.
_Avoid_: Tracked source

**Archive**:
Inactive configuration retained for reference or rollback but excluded from the current setup.
_Avoid_: Package, live configuration

## Agent configuration

**Primary harness**:
Codex, which owns the canonical global agent rules, shared skill catalog, and shared shell guardrail hooks.
Codex runs independent reviews through Codex CLI, Claude Code, and Antigravity CLI.
Shared MCP definitions live in `mcp/shared/servers.json`, and active shared Jev logic lives in `mcp/shared/jev.ts`.
Codex owns its pinned Jev and xAI Search registrations.
Historical Pi and OpenCode configurations live under `old/stow/`, and retired Pi tests live under `old/test/`.
_Avoid_: Default agent

**Shared skill catalog**:
The tracked set of agent skills made available to supported harnesses from one canonical source tree, `stow/codex/skills/shared/`.
_Avoid_: Claude skills, Pi skills

**Pi workflow catalog** *(archived)*:
Previously, Lauren Tan's pstack skills loaded by a community Pi adapter, separate from the tracked shared skill catalog.
Pi is retired; active pstack workflows run natively in Codex through Open Pstack, and the archived Pi configuration lives under `old/stow/pi/`.

**Baseline catalog**:
The stable Matt Pocock source that the shared catalog sync can import from, subject to recorded exclusions.
_Avoid_: Personalization layer

**Personalization layer**:
Dillon Mulroy skills eligible for shared catalog sync when they are not excluded and do not replace baseline or local skills.
_Avoid_: Baseline catalog, local skill

**Local skill**:
A skill owned by this repository and preserved independently of either upstream catalog.
_Avoid_: Personalization layer

**Skill ownership**:
The recorded source of authority for a skill, which determines whether synchronization follows Matt Pocock, Dillon Mulroy, or this repository.
Explicit local ownership preserves personalized skills against both upstream catalogs.
Excluded ownership keeps a deliberately removed upstream skill out of the catalog during synchronization.
_Avoid_: Skill location

**Harness adapter**:
A harness-specific wrapper or configuration that exposes shared behavior without creating another canonical implementation.
Codex shared MCP registrations (from `mcp/shared/servers.json`) and the Claude Code Jev mod copy (from `mcp/shared/jev.ts`) are generated by `scripts/harness_sync.sh`.
_Avoid_: Skill copy

**Global agent rules**:
User-scoped instructions shared across repositories and imported by supported coding-agent harnesses.
The canonical tracked file is `stow/codex/.codex/AGENTS.md`; the Claude Code Stow package exposes it through a relative symlink.
_Avoid_: Project rules

**Project rules**:
Repository-scoped instructions that describe local contracts, commands, and hazards without redefining global preferences.
_Avoid_: Global agent rules
